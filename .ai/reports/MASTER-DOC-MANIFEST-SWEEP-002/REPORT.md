⟹ **한 명제에 또 세 값.** 구 형태는 **꼬리에서 넓고**, 발주 교정형은 **머리에서 좁다** — **같은 병의 양끝**이다. 착지 문면은 「종료 앵커 깊이 = **앵커 깊이 이하**」(`###`→`^#{1,3} `, 실용형 `^#{2,3} ` / `##`→`^#{1,2} `)로 적었다. **게이트의 `SEC()` 는 `###` 앵커에만 쓰이거나(G5·G6·G7) 하위 절 없는 `##` 절에 쓰여(G2·G3) 실측상 무해**했다 — 확인 후 **게이트는 무수정**.

**⑥ T6 의 「`\|` 는 허용」이 옳은가 · 네 grep 은 GNU 인가.** → ★**직접 돌렸다. 「GNU냐 BSD냐」라는 이분법 자체가 내 환경에서 성립하지 않는다.**

| 자 | 실측 |
|---|---|
| `uname -s` | `Darwin` |
| `type grep` | ★**binary 아님 — harness 주입 shell function** → `ugrep 7.5.0` `-G` + `--ignore-files --hidden -I --exclude-dir=.git …` |

| `echo a \| grep -c 'a\|b'` / `echo z \| …` | **1** / **0** ⟹ `\|` = **교대로 동작** (두 grep 모두) |

⟹ **`\|` 허용 판정 = 유지**(강화 불요 · 발주가 지정한 조건 「BSD 면 강화」에 해당하지 않음). ★**그러나 발주 §0-ⓐ#4 / T6 의 실증 서술은 내 환경에서 반증된다** — 「macOS · BSD grep 이면 `\b` 미정의 ⟹ 항상 0」이 **거짓**이다(BSD grep 2.6.0 은 GNU 호환이라 `\b` 를 문다). 게다가 **집행자의 `grep` 은 두 후보 중 어느 것도 아닌 세 번째 것**(ugrep shim)이다. ⟹ **T6 의 명제는 강화되고 실증은 교체됐다**: 위험은 「flavor 가 패턴 의미를 바꾼다」보다 **「환경이 대상 집합을 바꾼다」**가 더 크다 — shim 의 `--ignore-files` 는 gitignore 된 file 을 **조용히 분모에서 뺀다**. 착지 문면(§0.7)은 이 실측 표를 그대로 담았고, **「전수 주장에는 쓴 grep 을 적는다」**를 처방에 넣었다. **음성대조**는 §7 에 재현.

**⑦ 「박음」 ↔ 「박제」 동의 여부 (= 발주가 판정 안 함).** → ★**다른 뜻이다. 통합하지 않고 둘 다 정의했다.**
