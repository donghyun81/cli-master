### ⑵ T5 가 옳은가 → **옳다. 다만 근거를 더 센 것으로 교체했다.**

발주 근거는 「무한 후퇴」였다. 실측으로 확인했다: `7224836`(backfill commit)의 sha 를 담은 file = **0** · `1dcf20f`(본체)를 담은 file = **1**(002 REPORT). 여기까지는 발주와 같다.

★**그런데 이건 후퇴가 아니라 불가능이다.** git 의 sha 는 **그 commit 자신의 내용에 대한 해시**다. commit 안에 자기 sha 를 넣으면 내용이 바뀌고 sha 도 바뀐다 — **고정점이 존재하지 않는다.** 「무한 후퇴」는 *다가갈 수는 있다*는 뉘앙스를 주지만, 실제로는 **한 걸음도 못 간다.** 그래서 §15.2 에 심은 K-156 은 「불가능」으로 적었다: 조항이 **집행 실패를 만든 게 아니라 애초에 충족될 수 없었다**.

★**반론(§9-2 이 스스로 제시한 것)은 자로 재현해 보니 성립하지 않는다.** 반론 = 「REPORT 만 보는 독자에게는 그 backfill commit 이 안 보인다」. 그런데 002 의 §정정 append 를 열어 보면 최종 ahead 를 **`7` = 진입 3 + 본 판 4(`d46f79c` · `0ac9d68` · `1dcf20f` · **본 정정 append commit**)** 로 적어 뒀다 — **아직 존재하지 않는 commit 을 포함한 상대식**이다. 즉 REPORT 만 읽는 독자도 **나열된 sha 3 개보다 ahead 가 1 크다**는 데서 꼬리 commit 의 존재를 안다. ⟹ 발주가 제안한 「후기입 여부 플래그」는 **이미 관례로 성립해 있던 것**이라 새 절이 필요 없다. 그 관례를 §15.2 에 **1 bullet 로 명문화**했다(= K-152-ⓑ 「ahead 는 상대식」과 같은 자리). **스키마 재설계 0**(§0-ⓒ 준수).
